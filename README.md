# 🌤️ 오늘의 하늘

현재 날씨부터 주간 예보와 대기질까지, 내가 궁금한 국내 도시의 정보를 한곳에서 확인하는 Vue 기반 날씨 서비스입니다.

세 도시의 임시 데이터를 출력하는 목업으로 시작해 컴포넌트 분리, Vue Router, Pinia, 외부 API를 단계적으로 적용하며 실제 데이터를 검색하고 저장할 수 있는 서비스로 확장했습니다.

## 주요 기능

### 지역별 현재 날씨

- 판교, 서울, 수원, 부산, 제주 5개 지역을 기본으로 제공합니다.
- 현재 기온, 날씨 상태, 습도, 풍속을 확인할 수 있습니다.
- 카드의 상세보기로 도시별 날씨와 대기질 페이지에 이동합니다.
- 섭씨·화씨를 전환하면 대시보드, 상세 화면, 주간 예보에 함께 적용됩니다.

### 국내 도시 검색과 저장

- 기본 지역 외의 국내 도시를 검색해 대시보드에 추가할 수 있습니다.
- 입력 중에는 이미 불러온 도시를 자동완성으로 제안합니다.
- 외부 API 요청은 글자마다 실행하지 않고 `도시 추가` 또는 Enter로 검색을 확정했을 때만 실행됩니다.
- 추가한 도시의 이름과 좌표는 `localStorage`에 저장되어 새로고침 후에도 유지됩니다.
- 실시간 날씨 값은 저장하지 않고 앱을 다시 열 때 최신 데이터로 조회합니다.

### 즐겨찾기

- 자주 확인하는 도시를 즐겨찾기로 지정할 수 있습니다.
- 즐겨찾기는 선택한 순서대로 목록 상단에 배치됩니다.
- 가장 먼저 즐겨찾기한 도시가 주간 예보의 기본 도시가 됩니다.
- 즐겨찾기 순서는 브라우저에 저장됩니다.

### 최대 7일 주간 예보

- 도시와 기간(3일, 5일, 7일)을 선택할 수 있습니다.
- 날짜별 날씨, 최고·최저 기온, 강수확률, 일출·일몰 시각을 제공합니다.
- 강수확률은 흰색에서 진한 파랑으로 이어지는 색상과 게이지로 표현합니다.
- 색상 외에도 물방울 아이콘과 수치를 함께 표시합니다.

### 시간과 날씨에 맞춘 화면

- 오늘의 일출·일몰 시각을 앱 상단에서 확인할 수 있습니다.
- 현재 시각과 날씨에 따라 낮, 비, 노을, 밤 테마로 변경됩니다.
- 현재 상태에 맞춰 우산, 일몰, 야간 외출 등에 관한 추천 문구를 보여줍니다.

### 대기질 정보

- 상세 화면에서 PM10, PM2.5, 통합대기환경지수(CAI)를 확인할 수 있습니다.
- 기본 5지역은 지정 측정소를 사용하고, 검색 도시는 해당 시·도의 유효한 측정소를 자동 선택합니다.
- API가 `-`를 반환하면 숫자로 오해하지 않도록 `측정 자료 없음`으로 안내합니다.

## 페이지 구성

| 경로 | 화면 |
| --- | --- |
| `/` | 날씨 대시보드와 도시 검색 |
| `/forecast` | 주간 예보 |
| `/about` | 서비스 소개 |
| `/weather/:id` | 도시별 날씨·대기질 상세 정보 |
| 그 외 주소 | 404 안내 화면 |

## 사용 방법

1. 홈에서 기본 5지역의 현재 날씨를 확인합니다.
2. 다른 지역이 필요하면 검색창에 국내 도시명을 입력합니다.
3. 자동완성에서 선택하거나 이름을 입력한 뒤 `도시 추가`를 누릅니다.
4. 별 버튼으로 자주 보는 도시를 즐겨찾기에 등록합니다.
5. `상세보기`에서 습도, 풍속과 대기질을 확인합니다.
6. `주간 예보`에서 도시와 기간을 선택합니다.
7. 상단 단위 버튼으로 섭씨와 화씨를 전환합니다.

## 실행 방법

### 요구 환경

- Node.js `20.19.0` 이상 또는 `22.12.0` 이상
- npm
- OpenWeather API 키
- 공공데이터포털 에어코리아 일반 인증키

### 설치와 환경변수

```sh
npm install
```

루트의 `.env.example`을 참고해 `.env`를 만듭니다.

```env
VITE_OPENWEATHER_API_KEY=OpenWeather_API_키
VITE_AIRKOREA_API_KEY=공공데이터포털_일반_인증키
```

`VITE_` 변수는 브라우저 번들에서 읽을 수 있습니다. `.env`는 저장소에 키가 올라가는 것은 막지만 배포된 프런트엔드에서 키를 완전히 숨기지는 못합니다. 운영 환경에서는 서버 또는 서버리스 함수가 API를 대신 호출해야 합니다.

### 개발과 빌드

```sh
npm run dev
npm run lint
npm run build
npm run preview
```

## Vercel 배포

- Framework Preset: `Vite`
- Build Command: `npm run build`
- Output Directory: `dist`
- Environment Variables: 위의 두 변수를 Production과 Preview에 등록

Vue Router의 직접 접근을 위해 `vercel.json`에 SPA rewrite가 설정되어 있습니다. GitHub의 `main`에 push하면 새 배포가 자동 생성됩니다. 과거 Deployment의 `Redeploy`는 그 당시 커밋을 다시 배포하므로 최신 커밋으로 생성된 Deployment를 사용해야 합니다.

## 기능 추가 과정

| 단계 | 확장 내용 | 핵심 학습 |
| --- | --- | --- |
| Day 1 | 임시 데이터 기반 날씨 목업 | `ref`, `v-for`, `v-if`, 이벤트 |
| Day 2 | 반응형 도시 검색 | `computed`, `watch`, `watchEffect` |
| Day 3 | 검색창·카드·레이아웃 분리 | props, emits, `<slot>` |
| Day 4 | 홈·소개·상세·404 페이지 | Vue Router, 동적 경로, Lazy Loading |
| Day 5 | 섭씨·화씨 전역 상태 | Pinia, composable |
| Day 6 | 실제 현재 날씨 | OpenWeather, 응답 정규화, 로딩·오류 |
| Day 7 | 대표 5지역과 UI 개선 | 병렬 요청, PrimeVue, AutoComplete |
| Day 8 | 최대 7일 예보 | Open-Meteo, 새 Store/View/Component |
| Day 9 | 일출·일몰 기반 테마 | 시간 계산, 추천 문구, App 리팩토링 |
| Day 10 | 사용자 도시와 즐겨찾기 | Geocoding, `localStorage`, 정렬·중복 제거 |
| Day 11 | 미세먼지 상세 정보 | AirKorea, 측정소 선택, 결측·지연 처리 |

처음에는 모든 상태와 UI가 한 컴포넌트에 있었습니다. 기능이 여러 화면에서 필요해질 때 Store와 composable로 옮겼고, 외부 API 응답은 API 계층에서 기존 카드가 사용할 형태로 변환했습니다. 기존 데이터 흐름을 유지하면서 필요한 기능을 한 단계씩 얹는 방식으로 개발했습니다.

## 프로젝트 구조

```text
src/
├── api/              # 외부 API 요청과 응답 변환
├── components/       # 공통 헤더, 검색, 날씨·예보 카드, 필터
├── composables/      # 날씨 요청, 온도 변환, 대기질, 화면 테마
├── router/           # 경로와 라우트 가드
├── stores/           # 단위, 도시·즐겨찾기, 주간 예보 상태
├── views/            # 홈, 상세, 예보, 소개, 404
├── App.vue           # 공통 레이아웃 조립
└── main.js           # Vue, Pinia, Router, PrimeVue 등록
```
