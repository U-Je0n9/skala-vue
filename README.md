# SKALA Vue 날씨 프로젝트

Vue 3의 기본 문법을 익히기 위해 지역별 날씨 화면을 만드는 프로젝트입니다.  
현재는 실제 날씨 API를 연결하기 전 단계로, 임시 데이터를 사용한 목업 화면을 구현했습니다.

## Day 1 - 날씨 목업 만들기

### 오늘 구현한 내용

- 서울, 수원, 부산의 임시 날씨 데이터를 `ref`로 관리했습니다.
- `v-for`를 사용해 날씨 데이터를 카드 목록으로 출력했습니다.
- 기온이 25도 미만이면 `선선함`, 25도 이상이면 `더움`이 표시되도록 `v-if`, `v-else`를 적용했습니다.
- 입력창의 값과 `searchCity` 상태를 연결해 현재 입력 중인 도시를 화면에 표시했습니다.
- 날씨 카드를 클릭하거나 `상세 보기` 버튼을 누르면 각각 다른 알림이 나타나도록 이벤트를 구현했습니다.
- 카드에 hover 효과를 추가해 클릭할 수 있는 요소라는 점이 잘 보이도록 했습니다.

목업 데이터는 다음과 같은 형태로 작성했습니다.

```js
const weatherList = ref([
  { id: 'city_01', name: '서울', temp: 28, status: '맑음' },
  { id: 'city_02', name: '수원', temp: 24, status: '비' },
  { id: 'city_03', name: '부산', temp: 26, status: '구름' },
])
```

### 트러블슈팅

#### 1. 한글 입력 시 상태 반영 방식 고민

처음에는 아래와 같이 `v-model`을 사용하려고 했습니다.

```html
<input v-model="searchCity" />
```

하지만 한글은 자음과 모음이 조합되는 IME 입력 방식이라 입력 도중 값이 기대한 시점과 다르게 반영될 수 있다는 점을 알게 되었습니다. 입력 이벤트를 직접 확인하기 위해 `:value`와 `@input`을 사용하도록 변경했습니다.

```html
<input
  type="text"
  :value="searchCity"
  @input="(e) => (searchCity = e.target.value)"
/>
```

이 과정에서 `v-model`이 내부적으로 값 바인딩과 이벤트 처리를 함께 제공한다는 것도 이해할 수 있었습니다. 이후에는 한글 조합 완료 시점까지 고려해 `compositionstart`, `compositionend` 이벤트가 필요한지도 확인해 볼 예정입니다.

#### 2. 상세 보기 버튼을 눌렀을 때 카드 클릭도 함께 실행됨

날씨 카드 전체에 클릭 이벤트가 있고, 카드 내부 버튼에도 별도의 클릭 이벤트가 있습니다. 처음에는 버튼을 클릭하면 버튼 이벤트뿐 아니라 부모인 카드의 이벤트까지 실행될 수 있었습니다. 원인은 자식 요소에서 발생한 이벤트가 부모 요소로 전달되는 이벤트 버블링이었습니다.

버튼에 `.stop` 이벤트 수식어를 추가해 부모 카드로 클릭 이벤트가 전달되지 않도록 해결했습니다.

```html
<button @click.stop="showDetails(weather.name, weather.status)">
  상세 보기
</button>
```

이를 통해 Vue의 이벤트 수식어를 사용하면 `event.stopPropagation()`을 직접 작성하지 않아도 된다는 점을 배웠습니다.

#### 3. 반복 렌더링 시 고유한 `key` 지정

처음에는 단순히 목록만 반복하면 된다고 생각했지만, Vue가 각 카드를 정확하게 구분하고 효율적으로 갱신하려면 고유한 `key`가 필요했습니다. 도시 이름 대신 데이터에 별도의 `id`를 만들고 `:key="weather.id"`로 연결했습니다.

```html
<div v-for="weather in weatherList" :key="weather.id">
```

데이터 순서가 변경되거나 항목이 추가·삭제될 때도 각 DOM 요소의 상태를 안정적으로 유지하기 위한 설정이라는 점을 알게 되었습니다.

#### 4. 화면에 따라 달라지는 문구 처리

온도에 따른 문구를 JavaScript에서 따로 가공할 수도 있지만, 이번에는 Vue의 조건부 렌더링을 연습하기 위해 템플릿에서 `v-if`, `v-else`를 사용했습니다.

```html
<span v-if="weather.temp < 25">❄️ 선선함 (25도 미만)</span>
<span v-else>🔥 더움 (25도 이상)</span>
```

조건이 단순할 때는 템플릿에서 바로 확인할 수 있어 이해하기 쉬웠습니다. 조건이 많아지거나 여러 곳에서 같은 판단을 사용하게 된다면 computed 또는 별도의 함수로 분리하는 편이 좋을 것 같습니다.

### 현재 확인한 개선점

- 검색 입력창의 `placehoder` 오타를 `placeholder`로 수정해야 합니다.
- 현재 검색어는 화면에 표시만 되고 있으므로, 다음에는 도시 목록 필터링 기능을 연결할 예정입니다.
- 현재 하나의 목업 컴포넌트에 검색창과 카드가 함께 있으므로 `WeatherSearch`, `WeatherCard`, `WeatherView`로 역할을 나눌 예정입니다.
- 목업 데이터 대신 실제 날씨 API를 연결하고 로딩 및 오류 상태를 처리할 예정입니다.
